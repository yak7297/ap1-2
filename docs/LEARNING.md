# 코드 이해하기

## 읽는 순서

`main.py → game.py → quiz.py → inputs.py → storage.py` 순서로 읽습니다. 처음에는 메뉴에서 퀴즈 풀기로 이동하는 흐름 하나를 따라가 보세요.

## 기초 문법과 실제 사용 위치

- 변수: 값을 이름으로 보관합니다. `correct`는 이번 게임에서 맞힌 문제 수입니다.
- `int`: 정답 번호와 점수 같은 정수입니다.
- `str`: 문제나 선택지 같은 글자입니다.
- `bool`: `played`처럼 참/거짓을 나타냅니다.
- `list`: `quizzes`처럼 여러 값을 순서대로 담습니다.
- `dict`: JSON으로 저장할 때 `"best_score": 80`처럼 이름과 값을 연결합니다.
- `if/elif/else`: 메뉴 번호에 따라 다른 메서드를 호출합니다.
- `while`: 올바른 입력을 받거나 사용자가 종료할 때까지 반복합니다.
- `for`: 문제나 선택지처럼 개수가 정해진 목록을 순회합니다.
- 매개변수: `read_number(prompt, minimum, maximum)`에 입력 문구와 허용 범위를 전달합니다.
- 반환값: `read_number()`가 검증한 정수를 `return`으로 돌려줍니다.

## 클래스와 객체

`Quiz`는 문제 한 개를 만드는 설계도입니다. `Quiz(...)`를 호출하면 실제 문제 객체가 만들어집니다. `__init__`는 객체를 만들 때 속성을 준비합니다. `self`는 현재 객체 자신입니다. `self.question`은 그 객체의 문제이며, `is_correct()`는 정답인지 판단하는 메서드입니다.

`QuizGame`은 문제 목록, 최고 점수와 메뉴를 관리합니다. 파일 처리는 `StateStore`에 분리했습니다. 최소 2개 요구보다 하나 많은 3개 클래스를 사용하지만 역할은 각각 문제/게임/저장으로 단순합니다.

## 저장과 예외 처리

`with path.open(encoding="utf-8")`로 파일을 열고 작업이 끝나면 자동으로 닫습니다. JSON은 리스트와 딕셔너리를 텍스트로 보관하는 형식입니다. `json.load()`로 읽고 `json.dump()`로 씁니다. 문제 객체는 직접 JSON에 쓸 수 없어 `to_dict()`로 바꿉니다.

`try/except`는 예상 가능한 실패를 안내하는 데 사용합니다. 예를 들어 `int("abc")`는 `ValueError`이므로 숫자를 다시 입력하게 합니다. `finally`는 정상 종료나 입력 중단 모두에서 저장을 시도합니다. 손상 파일을 읽으면 원본 백업을 시도한 뒤 기본 퀴즈로 실행합니다.

## 보너스: 랜덤 출제

`questions = self.quizzes.copy()`로 출제용 목록을 복사한 뒤 `random.shuffle(questions)`를 호출합니다. 원본 목록 순서는 보존됩니다. `shuffle()`은 전달받은 목록 자체를 바꾸고 `None`을 반환하므로 `questions = random.shuffle(...)`로 쓰면 안 됩니다.

## Git 명령어

| 명령 | 역할 | 이 프로젝트 상태 |
| --- | --- | --- |
| init | 로컬 Git 저장소 생성 | 실행함 |
| add | 다음 커밋에 포함할 변경 선택 | 실행함 |
| commit | 변경 내용을 기록 | 기능별로 실행함 |
| checkout | 브랜치 생성/전환 | feature/quiz-play 생성과 main 전환에 사용 |
| merge | 다른 브랜치 변경 병합 | main에서 기능 브랜치 병합 |
| push | 원격 저장소로 커밋 전송 | 실제 실행 및 캡처 완료 |
| clone | 저장소를 다른 폴더에 복제 | 실제 실행 및 캡처 완료 |
| pull | 원격 변경을 현재 저장소로 가져오기 | 실제 실행 및 캡처 완료 |

Git은 파일 변경 이력을 로컬에 기록하는 도구이고, GitHub는 Git 저장소를 온라인에 올리고 공유하는 서비스입니다. 구체적인 남은 실습은 SUBMISSION.md를 참고하세요.
